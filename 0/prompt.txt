  ## Design summary: the datasquare `/career` feature
  
  **Important caveat:** this is not a classic Q&A "mock interview" with per-answer scoring. It is a resume-driven, roughly 10-minute **career-coaching voice interview** that ends with a written report. The "card + map" mode exists only on the results page, as a 3-column layout. There is no toggle.
  
  Files: `/Users/aisandbox/Documents/datasquare/src/app/career/page.tsx`, `src/lib/career/{interview,recorder,jobs}.ts`, `src/components/career/JobMap.tsx`, `src/app/api/career/{start,turn,stt,tts,report,jobs,chat}/route.ts`, `supabase/migrations/20261007d_career_sessions.sql` and `20261008_career_results.sql`.
  
  ### A. AI voice interview
  - **Inputs and plan:** `/start` parses an uploaded or pasted resume with the existing parser. One LLM call (JSON mode) then returns a profile: headline, strengths, keywords, competitiveness and directions. The same call returns a ready-to-speak `opening` and a `plan` with a focus and 1–2 resume-specific questions for each of 5 fixed stages (goal, self-analysis, job criteria, role understanding, career plan). No company or role is entered up front; these are discovered during the interview.
  - **Turn loop:** the AI speaks, the user is recorded, the server transcribes, and `/turn` returns the next line. The server owns the transcript and the client only uploads user text.
    - The system prompt holds the stages, the plan, a resume summary and rules: one question per turn, at most 90 characters, a brief acknowledgement first, at most one follow-up when an answer is vague, and skip if asked.
    - The model returns JSON with `reply`, `stage` (can only move forward), `finished` and `notes`. Notes are extracted key facts such as target city or salary, merged into the session.
    - The opening line is reused from the profile, which saves one LLM call.
  - **Voice:**
    - Speech-to-text: browser `MediaRecorder` (webm or mp4) sent to a server endpoint using OpenAI `gpt-4o-mini-transcribe`. The browser Web Speech recognition is avoided because it doesn't work in China.
    - Recording stops automatically after 1.5 s of silence, after 15 s with no speech, or at a 60 s cap.
    - Text-to-speech: server OpenAI `gpt-4o-mini-tts` returning an mp3, falling back to the browser's `speechSynthesis`. It can only read transcript entry #i written by the AI, so it can't be used as a free TTS service.
    - Nothing is streamed; each step is a full request and response. Users can always type instead, and can interrupt the AI while it speaks.
  - **Scoring and feedback:** there is no per-answer score. `/report` produces JSON with a summary, strengths with evidence, gaps with advice, criteria, 3–5 roles (each with match 0–100, why, companies, salary, gap, next step), a timeline, 1/3/5-year plans, 2-week actions and interview tips. If parsing fails it retries once at a lower temperature.
  - **Storage:** one `career_sessions` row per interview holding the resume JSON, profile, transcript, notes, stage, turns, TTS/STT counts, report, status, cost, chat history and cached jobs.
  - **Cost controls:**
    - 6 sessions per IP per day, 14 AI turns, 40 TTS and 40 STT calls per session.
    - Input caps: 1,500 characters per user answer, 600 characters per TTS request, audio files up to 10 MB.
    - Every call's cost is added to `cost_usd`, and the model can be swapped with one environment variable.
  - **Interview screen:** a 5-stage progress bar, a timer (out of about 10:00), and a large animated advisor avatar that glows while speaking. Below it: a status line (speaking / listening with a level meter / thinking / transcribing), the latest AI line as a subtitle bubble, buttons (mic mute, interrupt, "I'm done", start speaking) and a collapsible full transcript.
  
  ### B. Card + map results
  - **Layout:** follow-up chat on the left, city chips and job cards in the middle, a Leaflet map with Google tiles (no key) on the right. City selection is shared between the chips and the map.
  - **Data:** a hardcoded table of about 40 city coordinates (`CITY_COORDS`). City names are normalized. Target cities come from the report's criteria. There is no climate or cost-of-living data.
  - **Pins:** one pill marker per city reading "company · city · n jobs", with a star for target cities and still shown when a city has no jobs. There is no clustering. Clicking a pin filters the cards and flies the map there; with nothing selected the map fits to all pins.
  - **Cards:** a match ring, title, tags (type, function, graduation year, salary), an AI reason and the company. There is no detail page; the card links straight to the external application page. Jobs are LLM-ranked from up to 2,000 rows in a read-only jobs database and cached on the session.
